Business rules agreed for the MyCup backend (services/controllers), decided 2026-06-10:

- **Scope:** only main aggregates get their own service + controller — Championship, Team, Match, UserUniverse, Dashboard. Format, ChampionshipRule, Phase, Group, GroupTeam, Round, PlayerChampionship are managed internally by the Championship aggregate (no standalone CRUD).
- **Championship Status/CurrentRound/TotalRounds:** computed dynamically from matches at query time (no DB column). No matches = draft; some finished = ongoing; all finished = finished.
- **Fixture/bracket generation (BE-008):** OUT of scope for now — CRUD + relationship management only.
- **Team scope:** teams are scoped per universe → `Team` needs `UniverseId` FK + migration; listings filtered by universe.
- **Player→team assignment (PlayerChampionship):** PES/FIFA style (1 player controls 1 full team). Two modes: random draw and manual assignment by the universe admin. `Championship.Distribution` = team distribution mode.
- **Group draw variable (manual | random | by pots/"potes"):** belongs to BE-008 group generation — deferred, not implemented now.
- **Authorization:** only `[Authorize]` for now (any authenticated user). Role enforcement (owner/admin/moderator via UserUniverse) deferred to BE-010.
- **Slug:** auto-generated by slugifying Championship.Name, unique within the universe.
- **Delete policies (per entity):**
  - Championship → cascade.
  - Universe → full cascade (championships, teams, players, members, history).
  - Player → soft delete (add `IsActive` to Player + migration; hide from listings).
  - Team → block with 409 Conflict if referenced by ChampionshipTeam / GroupTeam / Match.

Implementation order: Team → Championship → Match → UserUniverse → Dashboard. See [[backend-architecture-patterns]].
